Tokens & the Preprocessor

How the compiler reads your program — and the helper that works on it before the compiler even starts.

By the end of this lesson you can
  • cut any line of code into tokens and name each kind
  • tell keywords, identifiers, literals, operators and punctuators apart
  • explain white space, and use #include, #define and #ifdef
The big idea

Tokens are the words of C++

Before you can understand an English sentence, your brain cuts it into words and punctuation. The compiler does exactly the same with your code. The smallest meaningful pieces it finds are called tokens.

Class game

Count the tokens

Guess first, then type it in

int a = 5;  ·  cout << "Hi" << x;  ·  if (a >= 10) b++;

Answers

5 tokens · 6 tokens (cout << "Hi" << x ;) · 9 tokens (if ( a >= 10 ) b ++ ;). Remember: >= and ++ are one token each.

A compiler habit

The compiler always grabs the longest token it can

So >>= is one token (not three) and a+++b is read as a ++ + b.

  1. a+++b is cut as a ++ + b. The compiler takes ++ first (longest match), then the remaining +.
  2. Result. a++ uses 5, then makes a = 6. So r = 5 + 3 = 8, a = 6, b = 3.
Token kind 1

Keywords are reserved words

Picture it

Words like “Principal” or “Exit” on school doors are reserved for a purpose. You cannot rename your cupboard “Principal”. In the same way, a keyword already has a fixed meaning in C++ and cannot be used as your own name. Keywords are always written in lowercase.

Tricks

Colour changed in the editor? It is a keyword — hands off! Not keywords (common doubt): main, cout, cin, endl, include, string. They are identifiers that happen to be predefined.

Tell them apart

Literal = the value itself. Identifier = a name that points to a value.

In int age = 16; → age is the identifier, 16 is the literal. In cout << "age"; → "age" is a string literal (plain text), not the variable.

Token kinds 4 and 5

Operators do work. Punctuators organise.

Operators

Symbols that act on values (called operands).

+ - * / % = == && ++ << …

In 3 + 4: + is the operator; 3 and 4 are the operands. Lessons 5–7 cover them in depth.

Punctuators (separators)

Symbols that structure the code but calculate nothing.

; , ( ) { } [ ] #

Example: ; ends a statement, { } group statements.

The invisible token separator

White space: used to separate, then ignored

White space means space, tab and new line (comments are skipped too).

Needed when…

two tokens would otherwise glue together: int x (not intx), return 0 (not return0).

Optional when…

a symbol already separates them: a+b = a + b = a   +   b.

Kept inside…

string literals: "Hello World" keeps its space. Also, # lines need their own line.

Style matters

Legal does not mean readable! Use one statement per line and indent inside braces. White space is free — spend it kindly on the next reader (often you, next week).

Macros

A macro is a blind find-and-replace

It never calculates — it only pastes text. That can surprise you.

  1. Predict: 25? No, it prints 11. The preprocessor pastes 2 + 3 for x exactly as text, giving 2 + 3 * 2 + 3. Multiplication happens first: 2 + 6 + 3 = 11.
  2. The fix: brackets everywhere. ((2 + 3) * (2 + 3)) = 5 × 5 = 25. Rule: wrap every parameter, and the whole macro, in brackets.
Switching code on and off

#ifdef: compile this part only if a name exists

  1. #define DEBUG creates the name DEBUG. It does not need a value.
  2. #ifdef DEBUG — “if DEBUG is defined, keep the next lines.” It is, so the debug message stays.
  3. #else — this part is thrown away before compiling. It does not even run, it does not even exist.
  4. #endif closes the block. Delete line 4 and run again: the output flips to “Release mode”.

Lesson 4 recap

What we learned

✅ Tokens

  • Five kinds: K-I-L-O-P.
  • The compiler takes the longest token it can.
  • White space only separates tokens (kept inside strings).

✅ Preprocessor

  • Lines start with #, no ;, run before compiling.
  • Macros paste text — bracket every parameter.
  • #ifdef … #else … #endif switches code on or off.
