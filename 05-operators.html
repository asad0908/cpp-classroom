Sorting operators by how many operands they take

Unary, binary, ternary — count the operands

An operator is an action symbol. An operand is the value it acts on. In 3 + 4: operator +, operands 3 and 4.

1️⃣

Unary

One operand.

-x   !flag   x++   ~x   sizeof(x)

2️⃣

Binary

Two operands, one on each side.

a + b   a < b   a && b   a = b

3️⃣

Ternary

Three operands. C++ has exactly one: ?:

Remember

Unary = 1   Binary = 2   Ternary = 3  (uni-cycle, bi-cycle, tri-cycle)

Arithmetic

Two golden rules
  • int / int = int. The fraction is thrown away: 17 / 5 = 3. Make one side decimal to keep it: 17 / 5.0 = 3.4.
  • % works only on whole numbers.
See it work

Division and remainder

  1. Add and multiply behave as in maths: 17 + 5 = 22, 17 × 5 = 85.
  2. Integer division. Both operands are int, so the answer is an int: 17 ÷ 5 = 3.4, but the .4 is discarded, leaving 3.
  3. Remainder. 5 goes into 17 three times (15). What is left over is 2. So 17 % 5 = 2.
  4. One decimal operand makes the whole division decimal: 17 / 5.0 = 3.4.
Uses of the % operator

% is the most useful “small” operator

Even or odd?

n % 2 is 0 for even, 1 for odd.

Last digit

1234 % 10 = 4.

And 1234 / 10 = 123 removes it!

Clock arithmetic

(10 + 5) % 12 = 3: 5 hours after 10 o’clock is 3 o’clock.

Remember

% gives the remainder, and its sign follows the left operand: -7 % 3 = -1 and 7 % -3 = 1.

The famous exam topic

++ and --: add or subtract one

x++ and ++x both add 1 to x. The difference is what value the rest of the statement sees.

Prefix: ++x

Change first, then use.

Like pre-paid mobile: you pay first, then you talk.

Postfix: x++

Use first, then change.

Like post-paid mobile: you talk first, the bill (change) comes later.

Pre = change, then use.    Post = use, then change.

See it work

Trace the values, line by line

  1. Start: a = 5. b and c are empty lockers.
  2. b = a++; Postfix: use first. b receives the old value 5, then a becomes 6.
  3. Print: a=6 and b=5. They differ because b took the value before the increment.
  4. c = ++a; Prefix: change first. a becomes 7 first, then c receives 7.
  5. Print: a=7 and c=7. Both are the new value.
Exam warning

Never change the same variable twice in one statement, e.g. a = a++ + ++a;. The C++ standard calls it undefined behaviour, and Turbo C++ and modern compilers can disagree. Write one change per statement.

Comparing values

Relational operators answer yes (1) or no (0)

Biggest beginner bug

= stores a value. == compares two values. Writing if (a = 5) puts 5 into a (always true!) instead of asking whether a is 5. Say it out loud: single = is “becomes”, double == is “is equal to”.

See it work

Printing comparisons needs brackets

  1. (a < b) is true, printed as 1. (a > b) is false, printed as 0. C++ prints true/false as 1/0.
  2. Equal? 7 == 10 is false (0). 7 != 10 is true (1).
  3. Brackets matter! << has higher precedence than <= (you will see the full ranking in Lesson 7). Without brackets, cout << a <= 7 would be read as (cout << a) <= 7, which is an error.

Tricks

AND = all must be true. OR = at least one true.

In C++, 0 is false and every non-zero value is true: !5 is 0, !0 is 1.

See it work

Using logic on real conditions

  1. AND: age ≥ 15 is true, marks ≥ 60 is true. true AND true = 1.
  2. OR: age > 18 is false, marks > 90 is false. false OR false = 0.
  3. NOT: age > 18 is false (0), and ! flips it to 1. The brackets make ! apply to the whole comparison.
A lazy but clever habit

C++ stops as soon as the answer is known

A && B

If A is false, the answer must be false. B is never evaluated.

A || B

If A is true, the answer must be true. B is never evaluated.

  1. a != 0 is false, so the AND is already false. The right side ++b > 0 is skipped, so b is not incremented.
  2. So b is still 5. Short-circuiting has a visible effect!
  3. a == 0 is true, so the OR is already true. Again ++b is skipped, and the message “or” prints.
  4. b is still 5. Never put important changes (like ++b) on the right side of && or ||.
The only operator with three operands

? : — a one-line if-else

condition ? value_if_true : value_if_false
Picture it

A question and two answers: “Is it raining? take an umbrella : take sunglasses.” Exactly one of the two answers is chosen, and the other is never touched.

  1. (a > b) ? a : b — Is 8 > 12? No (false), so the second value, b = 12, is chosen and stored in big.
  2. Inside cout. 8 % 2 is 0, so a % 2 == 0 is true: the text "a is even" is chosen. Brackets keep the whole conditional together.
Nesting

It associates right-to-left (more on this in Lesson 7): n > 0 ? 1 : n < 0 ? -1 : 0 means n > 0 ? 1 : (n < 0 ? -1 : 0). This gives the sign of n: 1, −1 or 0.

Storing values

= means “calculate the right, store in the left”

✅ Valid

x = 10;
x = x + 5;  (read: new x = old x + 5)
a = b = c = 5;

❌ Invalid

10 = x;  (left side must be a variable)
x + 1 = 5;

Don’t read it as maths

In maths, x = x + 5 is impossible. In C++ it is perfectly fine, because = is an action, not a statement of equality. Assignment goes right to left, so a = b = c = 5 sets c first, then b, then a.

Writing less

Shorthand: a += 5 means a = a + 5

ShorthandSame asShorthandSame as

a /= ba = a / ba |= ba = a | b
a %= ba = a % ba ^= ba = a ^ b
The classic trap

The whole right side is calculated first. So a *= b + c means a = a * (b + c), not a = a * b + c.

See it work

Tracing the shorthand operators

  1. a = 10, then += 5 → 15.
  2. -= 3 → 12.
  3. *= 2 → 24.
  4. /= 4 → 6  (integer division).
  5. %= 4 → 6 % 4 = 2, and that is what is printed.
  6. x *= y + 1 → x = 3 * (4 + 1) = 15, not 3 * 4 + 1 = 13.

Lesson 5 recap

What we learned

✅ Arithmetic

  • Unary 1, binary 2, ternary 3 operands.
  • int / int = int. % = remainder.
  • Pre = change then use; Post = use then change.

✅ Conditions

  • Relational give 1 or 0; = vs ==.
  • ! > && > ||.
  • && and || short-circuit.

✅ Storing

  • c ? x : y is a one-line if-else.
  • = goes right to left.
  • a *= b + c means a = a * (b + c).
