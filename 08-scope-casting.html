Scope & Type Casting

Where can a variable be used? And how do we convert a value from one type to another? Two ideas that explain many “why did my program print that?” moments.

By the end of this lesson you can
  • tell local variables from global variables, and say where each can be used
  • explain scope vs visibility, and reach a hidden global with the scope resolution operator ::
  • predict implicit conversions and write explicit casts such as (float)a / b
The big idea

Scope = the region of the program where a name can be used

Picture it

Think of a school. A notebook in your bag is yours: only you can use it. A notice on the school board can be read by everyone. A variable is the same: some are private to a small area, some are visible everywhere.

🎒

Local variable

Declared inside a block { }. Usable only inside that block, after its declaration.

📝

Global variable

Declared outside every block (usually at the top). Usable everywhere below it.

A block is any piece of code between { and }.
Local scope

A local variable lives and dies inside its braces

  1. x belongs to the block of main — the outer braces. It is created here and lives until main ends.
  2. An inner block. y is created inside the inner braces, and the inner block can see the outer x, so x + y = 30.
  3. After the inner }, y is gone. Writing cout << y; here would be a compile error: “y was not declared in this scope”. But x is still alive and prints 10.
The visibility rule

Look outwards, never inwards

Global area — int g; visible everywhere
main’s block — int x; sees g and x
Inner block — int y; sees g, x and y
An inner block can use names from the outer areas, but an outer area can never see inside an inner block.
Global scope

Global variables live outside every block

  1. Declared outside main, so total and counter are global. They can be used by every block below this point (and, later, by every function).
  2. Globals start at 0. We never gave total a value, yet it prints 0. Global variables are automatically set to zero. (Local variables are not: they start with garbage.)
  3. An inner block can change a global. The change is visible everywhere because there is only one counter.
  4. Result: 101.

What if two variables share a name?

The inner name hides the outer name

Picture it

A class has two students called Rahul. When the teacher says “Rahul!”, the one nearest in that context answers. The other Rahul still exists — he is just hidden behind the name.

Scope

The region where a name is available.

Visibility

Whether the name can actually be seen right now. An inner variable with the same name can hide the outer one.

Lifetime

How long the variable exists in memory. A hidden variable is still alive.

Hidden ≠ dead. The outer variable is alive but hidden.
See it work

Three variables, all called x

  1. Global x = 10. Visible everywhere unless hidden.
  2. Local x = 20 inside main. It hides the global x for the rest of main.
  3. Innermost x = 30. It hides both of the others, so this prints 30.
  4. The inner block has ended, so the x = 30 is destroyed. The nearest x is now main’s x = 20: prints 20.
  5. ::x reaches the hidden global. The scope resolution operator :: with nothing on its left means “the global one”: prints 10.
The :: operator

:: says “the one that lives there”

::x — unary form

Nothing on the left: reach the global variable even when a local of the same name hides it.

std::cout — binary form

“cout that lives in std.” Same idea as the full name “Asad of 11-A”. This is what using namespace std; lets you skip.

Later in the course

:: also connects a class to its member functions, such as Student::display(). It is the operator with the highest precedence (level 1 on the ladder).

Type casting

Casting = converting a value from one type to another

Picture it

Pouring water from a big jug into a small glass loses some water. Pouring from a small glass into a big jug loses nothing. Type conversion works the same way.

Implicit (automatic)

The compiler converts for you, silently, when types are mixed.

Explicit (manual)

You ask for the conversion, using a cast.

In a mixed expression, the lower type is converted up to the higher type.  (int + double → double)
Going down loses data

Storing a double into an int throws away the decimal part: it truncates (it does not round). So int x = 3.99; stores 3.

  1. double → int. 3.99 is a double. Storing it in an int drops the .99 → x = 3.
  2. char → int. c + 1: the char 'a' (ASCII 97) is promoted to an int, so 97 + 1 = 98, a number, not a letter.
  3. int / int vs int / double. 7 / 2 stays int (3). In 7 / 2.0 the 7 is promoted to double, so the answer is 3.5.
Manual conversion

You decide: the cast operator

A cast converts the value being used. The variable itself keeps its own type.
See it work

Where you put the cast changes the answer

  1. int / int = int. 7 / 2 = 3. The .5 is lost.
  2. (float)a / b. A cast is a unary operator, so it binds tighter than /. It converts a to 7.0 first. Now it is float / int, and b is promoted: 7.0 / 2 = 3.5.
  3. (float)(a / b). The brackets make the division happen first: 7 / 2 = 3 (int). Only then is 3 cast to 3.0, which prints as 3. Too late — the fraction was already lost!
  4. static_cast<double>(a) is the modern spelling of the same idea. It is missing in Turbo C++ (see the red/green difference in Compare).

Lesson 8 recap

What we learned

✅ Scope & visibility

  • Local: inside { }, dies at }. Global: outside everything, starts at 0.
  • Inner names hide outer names; look outwards, never inwards.
  • ::x reaches the global x. std::cout names a member of std.

✅ Type casting

  • Implicit: small → big is automatic (char → int → float → double).
  • Big → small truncates: int x = 3.99; is 3.
  • Explicit: (float)a / b — cast first, then divide. (float)(a / b) is too late.
