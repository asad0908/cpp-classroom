Making Decisions

Until now every program ran from the first line to the last, in order. Today the program learns to choose: do this, or do that, depending on the data.

By the end of this lesson you can
  • explain flow of control and name its three kinds: sequence, selection, iteration
  • write if and if-else statements, and avoid the three classic traps
  • solve maximum of two and minimum of three numbers
The big idea

Flow of control = the order in which statements run

Picture it

A GPS says “go straight, go straight, go straight…”. But if the road is closed, it takes a turn. And at a roundabout it may send you round again and again. Programs do exactly the same.

➡️

Sequence

One statement after another, top to bottom. This is the default, and all we have used so far.

🔀

Selection

Choose which statements run. Also called branching or decision making.

🔄

Iteration

Run statements again and again. Also called looping or repetition.

Control statements decide which code runs and how many times.

Today

We start with the simplest decision makers: if and if-else.

Selection · one-way decision

The if statement: do it only when the condition is true

Picture it

“If it is raining, take an umbrella.” If it is not raining, you simply carry on.

What is a condition?

Usually a relational or logical expression from Lesson 5, which gives 1 (true) or 0 (false). C++ treats any non-zero value as true and only 0 as false.

See it work

A program that reacts to the marks

  1. Read the marks. The user types 72, so marks holds 72.
  2. The test. marks >= 35 becomes 72 >= 35, which is true (1).
  3. The body. Because the condition is true, everything between the braces runs: You passed! is printed.
  4. Outside the if. This line is not controlled by the if, so it runs every time. Run it again with 20: the condition is false, the braces are skipped, and only End of program appears.
Selection · two-way decision

if-else: choose between two paths

Picture it

“If it is raining, take an umbrella, else wear sunglasses.” You always do exactly one of the two.

Exactly one path runs: never both, never neither.
See it work

Even or odd?

  1. The test uses %. The remainder of n / 2 is 0 for every even number. For 7 it is 1, so 7 % 2 == 0 is false.
  2. The if part is skipped.
  3. The else part runs: 7 is odd.
  4. No braces here. When a branch has only one statement, the braces are optional. The next three slides show why we usually write them anyway.
Classic trap 1 of 3

Without braces, the if controls only one statement

  1. 3 > 5 is false.
  2. Only this line belongs to the if. It is skipped.
  3. This line looks like part of the if because of the indentation, but it is not. The compiler ignores indentation. It runs every time, so B is printed.
Always write the braces { }, even for one statement.
Classic trap 2 of 3

A stray ; after the condition kills the if

  1. The ; is a complete (empty) statement. C++ reads this as “if x > 5, do nothing”. The if ends right here.
  2. This is now an ordinary block, not the body of the if. It runs always, even though 3 is not greater than 5.
The program compiles and runs

No error message appears. The only clue is the wrong output, which is what makes this trap so sneaky.

Classic trap 3 of 3

= assigns, == compares

  1. x = 5 is an assignment, not a test. It stores 5 in x, and the value of the whole expression is 5.
  2. 5 is non-zero, so it counts as true. The body runs, even though x was 3 a moment ago.
  3. x was changed. It is now 5. The if silently damaged our data.
To compare, use ==.  if (x == 5)
Practice program 1

Find the maximum of two numbers

  1. Three lockers: two for the input, and one to hold the answer.
  2. Read both numbers. a = 15, b = 28.
  3. If a is bigger, the answer is a.
  4. Otherwise the answer is b. Here 15 > 28 is false, so largest becomes 28.
  5. Print the stored answer. If both numbers are equal, either branch gives the right answer.
Shortcut from Lesson 5

The whole if-else can be written in one line with the ternary operator: largest = (a > b) ? a : b;

Practice program 2

Find the minimum of three numbers

Picture it

A race. The first runner is the champion for now. Each new runner challenges the champion: if the challenger is faster (smaller time), the challenger becomes champion.

  1. Crown the first number. smallest = a; makes 40 the champion.
  2. Challenger b. Is 12 < 40? Yes, so smallest becomes 12.
  3. Challenger c. Is 25 < 12? No, so smallest stays 12. These are two separate ifs, not an if-else, because each challenger must get a turn.
  4. Print the champion: 12.
Trace it on paper

Follow smallest step by step  (a = 40, b = 12, c = 25)

Think about it

How would you change the program to find the largest of three? (Answer: flip each < to >, and rename the variable.) We will solve the same problem a second way in the next lesson, with nested ifs.

Quick check — 5 of 5

Which condition correctly tests that n is EVEN?

  • n / 2 == 0
  • n % 2 == 0
  • n % 2 = 0
  • n % 2 != 0
An even number leaves remainder 0 when divided by 2: n % 2 == 0. (= would assign, and != tests for odd.)
Lesson 10 recap

What we learned

✅ if and if-else

  • Three kinds of flow: sequence, selection, iteration.
  • if runs its body only when the condition is true. if-else runs exactly one of two paths.
  • 0 is false; any non-zero value is true.

✅ Traps and practice

  • Always use braces. No ; after the condition. Compare with ==, not =.
  • Maximum of two: if (a > b) … else …
  • Minimum of three: crown the first as champion, then let each challenger try.
