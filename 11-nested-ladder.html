Nested if & the else-if Ladder

Real decisions are rarely just yes or no. Sometimes one decision leads to another, and sometimes there are many choices. Two tools handle both.

By the end of this lesson you can
  • put one if inside another (nested selection) and find the largest of three numbers
  • say which if an else belongs to (the dangling else)
  • write an else-if ladder and explain why the order of its tests matters
An if inside an if

Nested selection: a decision that leads to another decision

Picture it

At a cinema door the guard asks first: “Do you have a ticket?” Only if yes, the next question is asked: “Are you old enough for this film?” The second question is reached only through the first.

How to read it

The inner if is just a statement inside the outer if’s braces. It is reached only when the outer condition is true.

Any statement can sit inside an if, even another if.
See it work

Ticket first, then age

  1. Two values in one cin. The user types 16 y: age = 16, hasTicket = 'y' (a char, so single quotes in the test).
  2. Outer test: hasTicket == 'y' is true, so we go inside the braces.
  3. Inner test: 16 >= 18 is false.
  4. The inner else runs: “Sorry, this show is for adults”.
  5. The outer else is only for people without a ticket. It is skipped here, and the inner question was never even asked for them.
Practice program

Largest of three numbers, using nested if

  1. First duel: a against b. 12 > 25 is false, so a has already lost. The winner must be b or c.
  2. The outer else: the winner of the first duel is b.
  3. Second duel: b against c. 25 > 40 is false.
  4. c wins: largest = c; gives 40.
  5. Print the answer. Only one of the four assignments ever runs.

Which if does this else belong to?

The dangling else: indentation can lie

  1. a = 5, so a > 0 is true. We go on to the next statement, which is another if.
  2. b = −2, so b > 0 is false. “both positive” is skipped.
  3. The else is attached to the nearest if (the one on line 8), no matter how it is indented. That if was false, so this else runs, and prints “a is not positive” although a is clearly positive!
An else pairs with the nearest unmatched if. Use braces to say what you mean.
Many choices

The else-if ladder: test one by one, take the first that fits

Picture it

A teacher reads out the rules: “90 or more: A. Else 75 or more: B. Else 60 or more: C…” She stops at the first rule that fits and ignores the rest.

Top to bottom. First true wins. The rest are skipped.
See it work

Marks to grade

  1. First rung: 82 >= 90 is false, so “Grade A” is skipped.
  2. Second rung: 82 >= 75 is true. “Grade B” is printed.
  3. The rest of the ladder is never even tested. Once a rung is chosen, C++ jumps to the end.
  4. Why not write marks < 90 && marks >= 75? There is no need: we only reach this test when the rung above was false, so marks is already below 90.
Classic trap

In a ladder, the order of the tests matters

  1. 95 >= 35 is true, and it is the very first rung.
  2. Grade D is printed for a student with 95 marks!
  3. These rungs can never run. Every mark that passes them has already passed 35 and been caught by the first rung.
Put the strictest test first, the loosest last.
Another trap

A ladder is not the same as a row of separate ifs

  1. 95 >= 90: true, A is printed.
  2. A new, independent if. 95 >= 75 is also true, so B is printed too.
  3. And again: C. Every separate if is tested, whatever happened before.

Lesson 11 recap

What we learned

✅ Nested selection

  • An if inside an if: the inner one is reached only through the outer one.
  • Largest of three: two duels, exactly two tests.
  • An else belongs to the nearest if. Use braces.

✅ The else-if ladder

  • Tests run top to bottom; the first true one wins and the rest are skipped.
  • Order matters: strictest test first.
  • Ladder = at most one branch runs. Separate ifs = every test runs.
