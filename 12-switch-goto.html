switch-case & goto

When one value decides among many fixed choices, a long ladder gets untidy. switch is built for exactly that. Then we meet goto, the jump that C++ has but good programmers avoid.

By the end of this lesson you can
  • write a switch with case, break and default
  • explain fall-through and use it on purpose (a calculator and a vowel checker)
  • choose between switch and an else-if ladder, and say why goto is not used
Selection · many fixed choices

switch: jump straight to the matching case

Picture it

In a lift you press 3 and it goes straight to floor 3. It does not stop at floors 1 and 2 to ask “is this yours?”

1 · Evaluate once

The expression in ( ) is worked out a single time.

2 · Jump to the match

Control jumps to the case whose value is equal.

3 · Run until break

break leaves the switch. No match? default runs.

See it work

A traffic light with switch

  1. The switch looks at light, which holds 'G'.
  2. 'R' does not match. Control skips this whole case. It does not run these lines.
  3. 'G' matches. We jump here: “Go” is printed, and break leaves the switch.
  4. default is the “none of the above” case. It is skipped here. Type a lowercase g and it runs, because 'g' and 'G' are different characters.

Equality only

switch can only ask “is it equal to this constant?” For ranges such as marks >= 75, use an else-if ladder.

The famous switch trap

No break? Execution falls through

  1. n is 2, so we jump to case 2.
  2. case 1 is skipped. We jumped over it.
  3. We land on case 2 and print “Two”.
  4. No break, so we keep going into the next case without testing it: “Three”. A case label is only a doorway, not a wall.
  5. And on into default: “Done”. The switch ends only at a break or at the closing brace.
After matching, C++ runs every line below until a break.

Practice program

A simple calculator

  1. One cin reads three things: 12 into a, the character * into op, and 4 into b.
  2. The switch examines the operator.
  3. The + and - cases are skipped.
  4. The * case matches: 12 * 4 = 48, then break.
  5. An if-else can live inside a case. Division checks for a zero divisor first, so the program never crashes.
  6. default catches any other character, such as %.
Using fall-through on purpose

Several cases, one block of code

  1. Five labels, one body. The first four have no statements and no break, so they fall through into the next label, until they reach the cout.
  2. Any of a, e, i, o, u lands here. For 'u' we print “u is a vowel” and break.
  3. Everything else is a consonant (we assume the user typed a lowercase letter).
Compare

Without fall-through you would need if (ch == 'a' || ch == 'e' || ch == 'i' || ch == 'o' || ch == 'u'). Stacked labels read more clearly.

Jump statement

goto: jump to a label, no questions asked

A label

A name followed by a colon, such as again:. It just marks a spot in the function. It does nothing by itself.

The jump

goto again; sends control to that spot at once, forward or backward, inside the same function.

See it work

Counting 1 to 3 with goto

  1. The label again: marks this spot.
  2. Print i, then add 1. First time: prints 1, i becomes 2.
  3. If i is still 3 or less, jump back to the label. This repeats the two lines above, so goto plus if behaves like a loop.
  4. When i reaches 4 the if is false, there is no jump, and we fall through to “Finished”.
The big warning

Why good programmers avoid goto

🍝

Spaghetti code

Jumps go up, down and across. You cannot read the program from top to bottom any more; you must chase labels like a tangled plate of spaghetti.

🐛

Hard to debug

At any line you cannot tell how control arrived there, because any goto in the function might have sent it.

🔧

Hard to change

Adding one line can silently break a jump far away. Programs with many gotos are tiring to maintain.

🏗️

We have better tools

Anything goto does can be written with sequence, selection and iteration (if, switch, for, while). This is called structured programming.

History

In 1968 the computer scientist Edsger Dijkstra published a famous letter titled “Go To Statement Considered Harmful”. Structured programming grew from that idea, and goto has been rare in good code ever since.

The better way

The same job with a for loop

  1. The whole loop in the header: start at 1, keep going while i <= 3, add 1 each round. No label, no jump, and the purpose is clear at a glance.
  2. Same output as the goto version, in fewer lines. Starting next lesson we study this loop properly.
In this course

You should know that goto exists, and you may meet it in old programs. Do not write it yourself. (A rare accepted use is escaping from several nested loops at once, and even then a function or a flag is usually cleaner.)

Which of these can NOT be used as the expression of a switch?

  • int count
  • char ch
  • float price
  • 'A' + 1
A switch works on whole-number types (int, char, enum). A float is not allowed. 'A' + 1 is an int, so it is fine.

Why is goto avoided by good programmers?

  • It is slower than a loop
  • It makes the flow hard to follow (spaghetti code)
  • It is not part of C++
  • It can only jump forward
goto exists and can jump both ways, but unrestricted jumps make programs hard to read, debug and change. Structured statements do the same job more clearly.

Lesson 12 recap

What we learned

✅ switch

  • Evaluates once, jumps to the matching case, runs until break. No match → default.
  • Works on int / char / enum, with constant labels and equality only.
  • Fall-through: no break means the next case runs too. Stack labels to share code.

✅ goto, and what to use instead

  • goto label; jumps to label: in the same function.
  • It leads to spaghetti code, so we use if / switch / loops instead.
  • Equal to a constant → switch. Range or complex test → else-if ladder.
