do-while, break, continue & Infinite Loops

The last loop, and the statements that let us leave a loop early or skip a round. Then the loop that never ends: how it happens, how to stop it, and how to end a whole program with exit(0).

By the end of this lesson you can
  • write a do-while loop and say how it differs from while
  • use break and continue and predict their output
  • spot an infinite loop, stop one, and end a program with exit(0)
Loop · test last

do-while: do it first, then ask whether to repeat

Picture it

You taste the soup first, and only then decide whether it needs more salt. You must taste at least once, because you cannot judge before tasting.

Do not forget

The semicolon after while (condition) is required. It is the only loop that ends with one.

See it work

Sum of the first 10 numbers, a third way

  1. do opens the loop. There is no test here, so the body is entered straight away.
  2. The body runs once, then the test. Add i to sum, then i++.
  3. The test is at the bottom: i <= 10. True? Jump back up to do. False? Carry on below. Note the ;.
  4. Same answer, 55. For a count like this all three loops agree. They differ when the condition is false at the very start.
The key difference

The condition is false from the start: while runs 0 times, do-while runs 1

  1. The while loop tests first. 5 < 3 is false, so its body is never entered. Nothing is printed under “while loop:”.
  2. The do-while runs its body before any test. It prints i = 5 and makes i equal to 6.
  3. Only now is the condition checked: 6 < 3 is false, so the loop ends. One round happened even though the condition was never true.
while: 0 or more times  ·  do-while: 1 or more times
Where do-while shines

Keep asking until the answer is valid

  1. We must ask at least once, because there is no age to check before the user types one. That is exactly what do-while guarantees.
  2. The condition describes a bad answer: under 1 or over 100. While the answer is bad, ask again.
  3. In the sample run 150 is rejected, −5 is rejected, 16 is accepted and the loop ends.
  4. Only a valid age reaches this line.

Jump statement · break

break: leave the loop right now

Picture it

A fire alarm rings in the middle of a lesson. Nobody finishes the lesson: everyone walks out at once. break does the same to a loop.

  1. The loop is meant to run 10 rounds.
  2. On round 4 the if is true and break runs. The loop ends immediately: the update i++ and the test are skipped.
  3. Rounds 1, 2, 3 printed their number before round 4 broke out.
  4. Control continues after the loop with i still 4: the number it had when we left.
Jump statement · continue

continue: skip the rest of this round, carry on with the next

Picture it

Playing a playlist, you skip one song you dislike and the next one starts. You do not leave the playlist; you only skip that song.

  1. Multiples of 3 (3 and 6) make this test true.
  2. continue abandons the rest of this round. The cout below is skipped, and the loop moves straight on to the update (i++) and the next test.
  3. All other numbers reach this line and are printed: 1 2 4 5 7. The loop still ran all 7 rounds.
Careful!

continue jumps to the test, so a while loop must update first

  1. The update comes first in this loop, before the continue can skip anything.
  2. On 3 and 6, continue jumps back to the test. i has already been increased, so the loop still moves forward.
The trap

If i++; were written after the if, then for i = 3 the continue would skip it. i would stay 3, the test would stay true, and the loop would repeat round 3 forever. (In a for loop this cannot happen, because continue still runs the update part of the header.)

The loop that never ends

An infinite loop: the condition never becomes false

Picture it

A roundabout with no exit. The car keeps going round and round until the petrol runs out. A program stuck in an infinite loop keeps burning the processor until somebody stops it.

✅ On purpose

Menus, games, servers and embedded devices should keep running until told to stop. They use while (1) or for (;;) with a planned exit.

❌ By mistake

A bug stops the condition from ever turning false. The program seems to hang, or fills the screen with the same line.

Remember

Any non-zero value is true (Lesson 10), so while (1) is always true. Modern C++ also accepts while (true), but Turbo C++ has no true, so we write 1.

Infinite on purpose

while (1) with a planned way out

  1. The condition is 1: always true, so by itself this loop would never end.
  2. Ask for a number on every round.
  3. The planned exit: when the user types 0, break leaves the loop.
  4. Otherwise add it and go round again.
  5. After the break, print the total. This does the same job as the total.cpp program from Lesson 14, written the other way round.
Spot the bug

Four ways to build an infinite loop by mistake

1 · The update is missing

while (i <= 5) { cout << i; }

Nothing ever changes i.

2 · The update goes the wrong way

for (i = 1; i <= 5; i--)

i gets smaller, so it is always ≤ 5.

3 · A stray semicolon

while (i <= 5);

The ; is the whole body, so nothing inside the loop can ever change i.

4 · = instead of ==

while (i = 1)

This assigns 1, and 1 is always true.

Before you run a loop, ask: what makes the condition false?

Getting out

How to stop an infinite loop

✌ From outside: the program is already stuck

  • Press Ctrl + C in the terminal or console window.
  • In Turbo C++ (DOS) press Ctrl + Break.
  • In an IDE press the Stop button (■), or close the console window.
  • Last resort: end the program in Task Manager.

Then fix the bug: stopping it does not repair it.

🛠 From inside: write a way out

  • Make sure something in the loop can turn the condition false.
  • Use break when a certain thing happens.
  • Use return to leave the function (in main, that ends the program).
  • Use exit(0) to end the whole program from anywhere. Next slide.
Ending the whole program

exit(0): stop the program, right here, right now

How to use it

Add #include <cstdlib> (in Turbo C++: <stdlib.h>), then write exit(0);

It ends the entire program immediately, even from deep inside a loop or another function. Nothing after it runs.

What the number means

The value is the exit status handed back to the operating system.

exit(0) = finished normally.
exit(1) (or any non-zero) = something went wrong.

StatementWhat it ends

Putting it together

A menu that runs forever until you choose Exit

  1. An infinite loop on purpose: the menu keeps coming back after every choice.
  2. Show the menu and read a choice on every round.
  3. Choices 1 and 2 print a message, and the loop goes round again (this is an else-if ladder from Lesson 11).
  4. Choice 0: say goodbye, then exit(0) ends the whole program on the spot.
  5. Anything else gets an error message and another go.
  6. This return 0; is never reached. The only way out of the loop is exit(0). The modern version keeps it because main normally ends with a return.

  • 45

Check yourself

Quick check — 4 of 5

Which of these is an INFINITE loop?

  • for (i = 0; i < 3; i++)
  • int i = 3; while (i > 0) i--;
  • int i = 1; while (i <= 5);
  • do { } while (0);
In the third one the stray ; is the whole body, so i stays 1 and 1 <= 5 stays true for ever. The others all finish.
Check yourself

Quick check — 5 of 5

What does exit(0); do?

  • Leaves only the current loop
  • Ends the whole program immediately
  • Skips to the next round
  • Restarts the program
exit(0) ends the entire program at once, from anywhere. The 0 means “finished normally”.
Lesson 15 recap

What we learned

✅ do-while, break, continue

  • do { } while (cond); tests last: it runs at least once. Note the ;.
  • break leaves the loop. continue skips to the next round.
  • In a while, update before a continue, or the loop may never end.

✅ Infinite loops and exit

  • while (1) / for (;;) loop for ever unless you add a way out.
  • Bugs: missing update, wrong direction, stray ;, = for ==.
  • Stop one with Ctrl+C (Ctrl+Break in Turbo C++). exit(0) ends the whole program.
